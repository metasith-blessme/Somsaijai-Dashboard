# สถานะรายได้เดือนสิงหาคม 2569 — ตรวจก่อนนำเข้าค่าใช้จ่าย

## คำเตือนสำคัญ

**ยอดขายเดือนสิงหาคมยังไม่ได้ลงใน Excel เลยแม้แต่บรรทัดเดียว** ทั้งสามสาขา ชีต `Aug26` ว่างเปล่าหมด

ถ้านำเข้าค่าใช้จ่าย ฿432,666.22 ตอนนี้โดยที่ยังไม่มีรายได้ ระบบจะคำนวณว่าเดือนสิงหาคม **ขาดทุน ฿432,666** ซึ่งไม่จริง และจะไหลต่อไปที่ loss carry-forward ของแต่ละสาขา กระทบส่วนแบ่งกำไรเดือนถัดไปด้วย

**ข้อเสนอ: ยังไม่ควรนำเข้าค่าใช้จ่ายอย่างเดียว** ควรนำเข้าพร้อมรายได้ หรือรอจนกว่ารายได้จะครบ

## ข้อจำกัดของตัวเลขชุดนี้

1. **ค่าประมาณคือค่าประมาณ** ตาม OCR_RULES ข้อ 9 ห้ามนำไปบันทึกเป็นยอดจริง ห้ามใช้รับรองความถูกต้อง และต้องติดป้ายว่าเป็น estimated ตลอดทาง ตัวเลขข้างบนใช้เพื่อ**ประเมินขนาดของช่องว่าง**เท่านั้น

2. **ตัวอย่างน้อย** วันพฤหัสและวันศุกร์มีข้อมูลอ้างอิงแค่ 2 วัน ช่วงของวันศุกร์กว้างมาก (฿3,904–฿7,329) ความแม่นยำจึงต่ำ

3. **ข้อมูล B1/B2 เป็น JSON ที่ผ่านการประมวลผลมาแล้ว ไม่ใช่หลักฐานต้นทาง** ตาม OCR_RULES ข้อ 2.5 JSON ที่สร้างขึ้นไม่ใช่หลักฐานต้นทางและนำมา backfill ไม่ได้ ต้องมีรูปรายงานขายจริงถึงจะบันทึกเป็น observed ได้ ส่วน B3 เป็น POS export ซึ่งเป็นหลักฐานระบบ ใช้ได้

4. ยอด B1/B2 JSON มีแต่ยอดรวมรายวัน **ไม่มีข้อมูลแยกเงินสด/สแกน จำนวนแก้ว หรือจำนวนขวด** ซึ่ง `auditRecord()` และการคำนวณ COGS ตามการใช้จริงต้องใช้

## ทางเลือก

**ทางที่ 1 — รอรูปเดือนสิงหาคมของ B1/B2** (แนะนำ)
อ่าน OCR จากรูปจริง ได้ทั้งยอด เงินสด/สแกน จำนวนแก้ว แล้วนำเข้ารายได้กับค่าใช้จ่ายพร้อมกัน ตัวเลขบน dashboard จะถูกต้องตั้งแต่แรก

**ทางที่ 2 — นำเข้าค่าใช้จ่ายก่อน แล้วรับสภาพว่าตัวเลขผิดชั่วคราว**
ไม่แนะนำ เพราะเดือนสิงหาคมจะแสดงขาดทุน ฿432,666 และถ้าเผลอ deploy ขึ้นเว็บ จะเห็นตัวเลขที่ผิด

**ทางที่ 3 — นำเข้าค่าใช้จ่าย + รายได้ B3 ที่ครบแล้ว**
B3 มีข้อมูลครบ 31 วันและเป็น POS export ที่ใช้ได้ จึงปิดงบ B3 เดือนสิงหาคมได้เลย ส่วน B1/B2 รอรูป
